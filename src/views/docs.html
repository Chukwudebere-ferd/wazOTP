Enterprise WhatsApp Gateway

Build something amazing with wazOTP.

wazOTP isn't just an OTP service—it's a high-speed WhatsApp API gateway designed to help you communicate with your users programmatically. Whether it's 2FA, transaction alerts, or automated notifications, we've got you covered. Best of all, there is no need to install Baileys, WebSockets, or any WhatsApp SDKs on your application. Just make standard HTTP requests, and we handle the heavy lifting.

Lightning Fast

Messages are dispatched in under 2 seconds via the Baileys engine.

Secure 2FA

Built-in OTP generation and verification with expiration logic.

Scalable

Log every message and monitor session health in real-time.

🌍 Global Phone Format

To ensure delivery worldwide, always use the E.164 standard (Digits only, including country code).

• Correct: 2348031234567 (Nigeria), 14155550123 (USA)
• Incorrect: +234... or 0803...

Note: For local Nigerian developers, our system automatically converts numbers starting with "0" to the correct international format.

All API requests must be authenticated using a secret API Key. You can find your key in the Dashboard.

HTTP Header

Messaging

Send Notifications

Use this endpoint to send custom WhatsApp messages. Perfect for transaction alerts, welcome messages, or order updates.

POST /v1/messages/send
cURL
curl -X POST https://wazotp.elzipodev.cv/v1/messages/send \
  -H "Authorization: Bearer sk_live_YOUR_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "to": "+2348012345678",
    "message": "Hello! Your account login was successful from a new device.",
    "event": "security_alert"
  }'
Node.js (Fetch)
const response = await fetch('https://wazotp.elzipodev.cv/v1/messages/send', {
  method: 'POST',
  headers: {
    'Authorization': 'Bearer sk_live_YOUR_API_KEY',
    'Content-Type': 'application/json'
  },
  body: JSON.stringify({
    to: '+2348012345678',
    message: 'Hello! Your account login was successful from a new device.',
    event: 'security_alert'
  })
});
const data = await response.json();
Python (Requests)
import requests

url = "https://wazotp.elzipodev.cv/v1/messages/send"
headers = {
    "Authorization": "Bearer sk_live_YOUR_API_KEY",
    "Content-Type": "application/json"
}
payload = {
    "to": "+2348012345678",
    "message": "Hello! Your account login was successful from a new device.",
    "event": "security_alert"
}

response = requests.post(url, json=payload, headers=headers)
print(response.json())

3. Retrieve OTP History

POST /v1/otp/retrieve

Query your OTP records with filters, field selection, sorting, and pagination. OTP codes are masked by default for security.

cURL
curl -X POST https://wazotp.elzipodev.cv/v1/otp/retrieve \
  -H "Authorization: Bearer sk_live_YOUR_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "filters": {
      "status": "verified",
      "date_from": "2026-01-01T00:00:00Z"
    },
    "fields": ["id", "phone", "status", "created_at"],
    "pagination": { "page": 1, "limit": 20 },
    "sort": { "by": "created_at", "order": "desc" }
  }'

Filter Options

• status: verified, unverified, expired, pending, or all
• phone: Filter by recipient phone number
• date_from / date_to: Filter by creation date range (ISO 8601)
• fields: Choose response columns (id, phone, code, status, created_at, expired_at, verified_at)
• pagination: page (default 1), limit (default 20, max 100)
• sort: by (created_at, phone, expired_at), order (asc, desc)

Infrastructure

Session Management

The dashboard uses these endpoints to manage your WhatsApp connection. You can also use them to monitor connectivity health.

GET /v1/whatsapp/session/status
Returns the current connection status (e.g., connected, qr_ready).
POST /v1/whatsapp/session/pair
Link with a phone number instead of QR. Send { "phone": "2348012345678" } to get an 8-character pairing code, then enter it in WhatsApp: Settings → Linked devices → Link a device → Link with phone number instead.
POST /v1/whatsapp/session/relink
Forces a session reset and generates a fresh QR code.
Troubleshooting

Error Codes

wazOTP uses standard HTTP response codes to indicate the success or failure of an API request.

HTTP error codes and meanings
Code Meaning Description
400 Bad Request Required parameters are missing (e.g., phone or message).
401 Unauthorized Missing or invalid API key in the Authorization header.
403 Forbidden You do not have permission to access this resource.
429 Too Many Requests You have exceeded the rate limit. Slow down your requests.
500 Internal Server Error WhatsApp connection is down or a database error occurred.
Common Questions

Frequently Asked Questions

Does the OTP get passed by the developers?

No. The developer does not generate or pass the OTP. For maximum security, wazOTP automatically generates the 6-digit code internally and sends it directly to the user's WhatsApp. The developer only passes the user's phone number to trigger the OTP, and then later passes the code the user typed in to verify it.

Do I need to install Baileys or any WhatsApp SDKs?

No. wazOTP acts as an independent REST API gateway. You don't need to install @whiskeysockets/baileys, WebSockets, or any heavy SDKs on your application servers. Just make standard HTTP requests (like using fetch or axios) and our engine handles all the complex WhatsApp connection logic for you.
